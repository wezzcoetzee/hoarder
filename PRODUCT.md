# Product

## Platform

macos

Native SwiftUI menu bar app (macOS 14+, `LSUIElement`, no Dock icon): a popover from the menu bar label and a Settings window. Impeccable has no dedicated macOS reference; treat it as native and follow macOS conventions (menu bar extras, popovers, keyboard shortcuts, system materials and controls), not web patterns. The `hoarder` CLI also builds on Linux, but only as the agent the app runs on remote devices; it has no UI of its own beyond text and JSON output.

## Users

Developers who run many coding agents (Claude Code, Codex, Cursor, T3) on a Mac and on a few other machines on their tailnet. Agent work leaves git worktrees, node_modules, Docker build cache, images and volumes, and package manager caches behind, and the disk fills without warning. They glance at the menu bar to see free space, open the popover when it turns amber, decide what to reclaim, and get back to work. The author is the first of these users; others install from GitHub Releases.

## Product Purpose

Hoarder watches free disk space and finds what agent coding leaves behind. Each finding gets a verdict (reclaimable, review, keep) and the exact command that reclaims it. Success is getting from "disk is low" to "space reclaimed, nothing important lost" in one popover visit, on this Mac or any watched device.

## Positioning

What a generic disk cleaner cannot truthfully claim:

- **Knows dev leftovers.** It understands worktree state (orphaned, merged, dirty, locked, stale), node_modules idleness, Docker volumes by kind (registry, BuildKit state, unused), and per-tool caches, not just large folders.
- **Verdict plus the literal command.** Every row shows what it will run. Nothing hides behind a generic Clean button.
- **Never deletes on its own.** Read-only until the user presses Run. No auto-clean, no background deletion, even for reclaimable rows.
- **One popover, many machines.** Linux and Mac devices on the tailnet are watched and cleaned from the same popover over plain `ssh`, with no server, daemon or open ports.

## Operating Context

- Lives in the menu bar. The label shows free space and turns amber below `alertBelowGB`; one notification per dip, Snooze silences for a day.
- Free space is checked every minute; a full scan runs on an interval (default 60 min) and takes about 45s, mostly `du` over node_modules.
- Popover: a device strip on top (⌘1 to ⌘9), a summary of safe and review totals with Clean safe, then sections (Caches, Worktrees, node_modules, Docker) of rows. Click a row to see its command, then Run. Kept rows can be force-cleaned behind a red warning.
- Settings window: General (open at login, intervals, config file) and one page per machine (limit, project folders, Test connection, Remove). Saves to `~/.config/hoarder/config.json`, writing only non-defaults; goes read-only while the file does not parse.
- Remote devices are reached with `ssh -o BatchMode=yes`; unreachable devices show a reason and its fix.
- Setup can be driven by a coding agent via `.claude/skills/setup-hoarder`.

## Capabilities and Constraints

- Verdicts: **reclaimable** (nothing lost by deleting now), **review** (probably dead weight, look first), **keep** (in use; cleanable, never suggested). These three words and their meanings are fixed product terminology.
- Clean safe runs every reclaimable row's command one at a time, after confirmation.
- Rows with no command (Docker VM disk, app data, tmpfs `/tmp`) only show where they are.
- Free space is the `df` figure, not Finder's (which counts purgeable space).
- Not notarized; first launch needs Open Anyway or clearing quarantine.
- Known gaps the UI must not paper over: tool-noise-only changes count as dirty, squash merges show as unmerged, pnpm/bun node_modules sizes overstate what deleting frees, Intel Mac devices need an Intel build.

## Brand Commitments

- Name: Hoarder. App icon at `Support/AppIcon.svg` (`.icns` generated by `scripts/make-icon.swift`).
- Voice: plain, terse, factual. Say what a thing is and what will happen ("rebuilt on next build", "re-downloaded when needed", "folders gone, tidies git's list"). No marketing language, no em dashes.

## Evidence on Hand

- README screenshots in `docs/screenshots/` (menubar, overview, confirm, clean-safe, force, full-list, settings), rendered from the made-up report `scripts/screenshots/report.json` and state files in `scripts/screenshots/states/`. Regenerate with `./scripts/screenshots.sh`. No real user paths ship.
- `swift run HoarderApp --snapshot <report.json|none> <out.png> [state.json]` renders the popover, menu bar label, or Settings window for any state without the menu bar.
- No testimonials, user counts, benchmarks or press exist. Do not invent them.

## Product Principles

1. **Show the command, then let the user run it.** Transparency over convenience; the user always sees what will execute before it does.
2. **The verdict carries the decision.** A glance at the verdict should be enough to act; detail is there on demand, not in the way.
3. **Nothing is lost by surprise.** Destructive paths for in-use items stay possible but always sit behind an explicit warning.
4. **Every machine is the same machine.** A remote device gets the same verdicts, rows and Run as This Mac; only its name changes.
5. **Glanceable first.** The menu bar label and popover header answer "am I OK?" before anything else.
